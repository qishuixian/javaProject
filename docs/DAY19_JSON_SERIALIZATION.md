# Day 19：JSON 序列化

## 今日目标

把 Teacher 对象转换成 JSON 文本，再从 JSON 文本解析回 Teacher。序列化是“对象 → 文本”，反序列化是“文本 → 对象”。

入口：[Day19Json.java](../java-basics/src/Day19Json.java)。在 IDEA 点击 main 左侧绿色三角运行。

## 1. 为什么需要 JSON

Java 对象只能存在于当前程序内存，HTTP 和文件需要文本或字节。JSON 是常见的数据交换格式：

```json
{"id":10001,"name":"张老师"}
```

本课为了不引入新的依赖，手写一个**只支持本练习两字段**的教学解析器。它不是生产级 JSON 库，不支持数组、嵌套对象、布尔值、null 或所有 Unicode 转义；真实项目必须使用 Jackson 等成熟库。

## 2. 序列化：对象变文本

```java
return "{\"id\":" + teacher.getId()
        + ",\"name\":\"" + escape(teacher.getName()) + "\"}";
```

外层 JSON 对象用 `{}`，字段名和字符串用双引号，数字不加引号。姓名中的双引号、反斜杠和换行必须转义，否则生成的 JSON 结构会被破坏。

```text
Teacher(10001, 张"老师)
        ↓
{"id":10001,"name":"张\"老师"}
```

## 3. 反序列化：文本变对象

解析器先确认大括号，再按未处于字符串内部的逗号分割字段，找到 `id` 和 `name`，最后调用 `new Teacher(id, name)`。调用构造方法很重要：ID 和姓名仍使用 Day6 的对象校验。

字段缺失、未知字段、引号不完整、ID 不是数字都会拒绝。拒绝格式错误比静默使用默认值安全；真实接口还要区分客户端错误和服务端错误。

## 4. 类型与字段边界

```json
{"id":"10001","name":"张老师"}
```

这里 id 是字符串，不是本课要求的数字，解析会失败。字段名大小写也按本课严格匹配；生产 API 要依据接口契约决定是否允许未知字段和兼容旧字段。

JSON 解析后得到的是新 Teacher 对象，不能用 `source == restored` 判断相同；应比较 ID 和姓名等业务内容。这个练习使用 `source.getName().equals(restored.getName())`。

## 5. 输出预期

```text
序列化：{"id":10001,"name":"张\"老师"}
解析后：10001 / 张"老师
内容一致：true
拒绝 JSON：缺少 id 或 name
拒绝 JSON：For input string: "abc"
拒绝 JSON：未知字段："extra"
```

## 6. 与目标项目的联系

aic-teaching-service 的 Controller 请求体、响应 DTO、Feign 调用和配置 JSON 都依赖序列化框架。阅读真实代码时关注字段命名、日期格式、未知字段、null、枚举和异常转换；不要把本课手写解析器用于生产接口。

当前项目的 POM 没有单独声明 Jackson 依赖名，但 Spring Boot 通常通过 Web/公共依赖带入 Jackson；具体以 Maven dependency:tree 和实际 import 为准。
